# 未確認事項リスト (Open Verification Items)

## 目的

**実装・記述はしたが、まだ確かめていないこと**を 1 か所で管理する。
これまでは docs/24 の各節の「未実施」や README の注記に散らばっていて、
何が残っているかを一覧できなかった（2026-11-04 オーナー指摘）。

- 本書に載っていない項目は「確認済み」か「未着手の機能」のどちらか、という状態を保つ。
- 「確かめる手段がまだ無い」ものも載せる（治具待ち・リリース待ちなど）。

## スコープ

| 含む | 含まない |
|------|----------|
| 実装済みだが実機・実環境で未確認の挙動 | 未実装の機能（→ [06_roadmap.md](06_roadmap.md)） |
| README・ガイドなど利用者向けの記述のうち、未確認の主張 | 要求と検証の対応の抜け（→ [23_traceability.md §4 GAP](23_traceability.md)） |
| 計画した試験のうち未実施のもの（docs/24 からの転記） | 既知の制約・設計上の割り切り（→ 各要求の注記・ADR） |

## 運用

1. **起票**: 未確認のまま実装・記述を入れるときは、同じ変更でここに 1 行足す
   （コミット前に。「後で書く」はしない）。
2. **確認**: 実施したら「完了」へ移し、日付・結果・記録先（docs/24 の節やコミット）を書く。
   FAIL なら欠陥として扱い、修正の後に再確認する（完了には移さない）。
3. **リリース**: 「リリース前」が **必須** の項目が残っている間はタグを打たない
   （[25_release_strategy.md §4](25_release_strategy.md) のチェックリストの入力）。
4. 元の文書（docs/24 など）の「未実施」の記述は残し、本書の ID を添える。正本は本書。
